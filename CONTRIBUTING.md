# Contribuer à SmartQueue

## Avant de commencer

- Créez une branche dédiée, avec un nom explicite (`feature/...`, `fix/...`, `docs/...`).
- Ne versionnez aucun secret, fichier `.env`, export de base de données ni artefact généré.
- Gardez chaque changement ciblé et documentez les impacts fonctionnels.

## Avant une demande de fusion

1. Mettez à jour la documentation si le comportement ou la configuration change.
2. Exécutez le lint, le build et les tests du composant concerné.
3. Vérifiez que l’interface reste utilisable en français, arabe et anglais lorsque votre changement touche le mobile.
4. Décrivez le problème résolu, la solution et la manière de la vérifier.

## Messages de commit

Préférez des messages courts à l’impératif : `feat: ajouter la recherche d’agence`, `fix: corriger le statut du ticket` ou `docs: préciser l’installation`.
